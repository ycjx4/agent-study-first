# Lesson Design and Assessment Alignment

## Core Contract

Teaching quality determines scope, length, and lesson count. Build complete coverage before compressing prose.

## Required Coverage Map

Before writing a lesson, record for every concept ID:

- learning objective
- prerequisites
- definition
- mechanism
- boundary or non-example
- worked example
- whether it affects mastery
- mapped questions and evidence type
- split decision when the preferred length cannot carry the complete unit

## Question Types

| Type | Contract | Affects mastery |
|---|---|---|
| `core` | The lesson directly taught the required method. | yes |
| `transfer` | Only the context changes; no new method is required. | yes |
| `exploration` | May go beyond the lesson and is visibly labeled. | no |

Every scored question names its concept IDs, type, and expected evidence.

## Reverse Alignment Check

For each scored question, derive a minimally acceptable answer and enumerate every decision, step, field, evidence criterion, and comparison it requires. Trace each requirement to the lesson.

For a procedural or design question, label each operation's instructional form. An operation is covered only when the lesson provides both (a) an execution rule telling the learner how to perform or choose it and (b) a worked demonstration or guided practice showing that operation inside a complete method. For each operation, cite and label both `execution rule` and `demonstration/guided practice`. A goal, principle, or high-level checklist establishes topic presence but is not execution support, and the question text is not teaching evidence.

Use this required operation-by-operation trace for every procedural or design question:

| Operation | Minimally required performance | `execution rule` citation | `demonstration/guided practice` citation | Result |
|---|---|---|---|---|
| O1 | [one operation] | [lesson citation or `missing`] | [lesson citation or `missing`] | pass / fail |
| O2...On | [one row per remaining operation] | [lesson citation or `missing`] | [lesson citation or `missing`] | pass / fail |

A complete trace contains a separate row for every operation O1 through On. An aggregate description is not a complete trace. If the requested response format cannot display a table, serialize every O1...On row without omission inside the designated coverage field.

If either instructional form is absent for any mastery-bearing operation, stop grading, classify an `instruction gap`, and exclude the question from learner status until teaching is repaired. If the question itself is mis-scoped or mismapped to the intended teaching, classify an `assessment gap` and exclude it until the assessment is repaired.

## Scope and Splitting

Preferred length is a reading preference, not a cap. Expand naturally when one concept needs more room; split when concepts have a dependency boundary or require separate worked examples. Never pre-cap lesson count or omit a definition, mechanism, boundary, counterexample, worked example, or scored-question support to meet a length target.

## Preflight Checklist

- all mastery-bearing objectives have complete coverage
- every scored question maps to taught material
- exploration questions are labeled and non-scoring
- prerequisites for the next lesson are identified
- split decisions preserve coherent learning units
