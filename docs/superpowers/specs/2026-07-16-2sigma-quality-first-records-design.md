# 2sigma 质量优先教学与细粒度学习记录设计

> 日期：2026-07-16
> 状态：已完成对话设计确认，等待书面审阅
> 适用范围：单个正在进行的课程，不包含历史课程检索或 SQL 存储

## 1. 背景与问题

当前 2sigma 已具备追问、补救、间隔复测和学习日志，但真实教学暴露出四类缺陷：

1. 正文只给出原则级说明，习题却要求用户自行构造未被讲解的方法。
2. 用户答案方向大致正确但仍明确困惑时，系统可能过早标记 `solid`。
3. 固定篇幅和预计文档数会推动内容压缩，使教学覆盖服从形式限制。
4. `_progress.md` 同时承担当前状态和历史证据，容易出现“已掌握”与“仍有关键困惑”并存的矛盾。

《思考，快与慢》08.md 的人工改判题是核心实例：正文只简述“记录并比较人工与规则”，但题目要求完整设计两份事前预测、证据、时间、真实结果和批量比较。相关方法在补充文档中才得到完整讲解，因此该困难首先是教学覆盖和题目对齐问题，不能直接归因于用户。

## 2. 目标

- 让教学质量决定篇幅、课程拆分和文档数量。
- 保证所有计入掌握判定的题目都有充分的正文教学支持。
- 区分学习缺口、教学缺口和题目设计缺口。
- 将掌握度从文档级总评细化为概念级状态和证据。
- 让用户自报困惑和置信度成为正式评估信号。
- 用短小的当前快照和详细的追加日志支持新会话准确接手。
- 保持 Markdown 人类可读、Git 友好，并为未来数据库迁移保留稳定结构。

## 3. 非目标

- 本版不实现 SQLite 或其他数据库。
- 不检索或分析历史课程。
- 不自动同步或推送 GitHub。
- 不为缺少原始证据的旧课程记录虚构置信度或掌握细节。
- 不把文档长度、预计篇数或学习速度作为高于教学质量的约束。

## 4. 核心原则

### 4.1 教学质量优先

先确定完整教学覆盖，再决定篇幅和拆分。只有在不损害定义、机制、边界、反例、示例和练习支持的前提下才精简。

用户选择的文档长度表示阅读偏好，不是字数上限。一个主题无法在目标篇幅内讲清时，应自然展开或拆成多课。文档数由学习依赖关系决定，不预先封顶。

### 4.2 教学责任先于用户归因

用户答不出时，先检查正文是否充分教授了题目所需方法，再评价用户掌握程度。系统不得把自身讲解不足记录成用户误区。

### 4.3 概念证据先于整体印象

每个概念独立记录状态、证据、困惑和复测要求。一篇文档内可以同时存在 `solid`、`provisional` 和 `remediating` 概念，不能用“整篇通过”覆盖差异。

### 4.4 用户困惑拥有否决权

用户明确表示实质性困惑时，该概念不能标记 `solid`。困惑不必自动阻止整个课程推进，但必须触发一次针对性诊断，并记录处理结果。

## 5. 教学覆盖与课程生成

每篇学习文档生成前，导师必须建立教学覆盖清单：

- 本课概念 ID 与学习目标。
- 每个目标需要的前置概念。
- 正文必须包含的定义、机制、边界、反例和完整示例。
- 哪些目标会进入掌握判定。
- 每道题对应的正文目标和证据类型。
- 当前篇幅能否完整承载；不能时如何拆课。

正文完成后进行一次反向检查：从每道计分题的合格答案追溯其所需知识。只要标准答案依赖正文未教授的方法，该题就不能作为掌握门槛。

## 6. 习题类型与对齐规则

每道题必须标记一种类型：

| 类型 | 要求 | 是否影响掌握 |
|---|---|---|
| `core` | 正文已直接教授核心工具 | 是 |
| `transfer` | 只更换场景，不引入新方法 | 是 |
| `exploration` | 可以超出正文，引导进一步思考 | 否 |

`exploration` 必须明确标注为探索题。答不出、跳过或提出疑问都不能降低掌握状态，也不能触发补救。

题目对齐失败时，不继续评价用户，而是将问题分类为 `assessment gap`，废弃、重写或降级为探索题。

## 7. 缺口诊断与教学动作

### 7.1 `learner gap`

正文覆盖充分，但用户无法解释、迁移或识别边界。生成 `XX-revisit.md`，用不同角度重新教学，并针对真实误区复测。

### 7.2 `instruction gap`

正文没有充分覆盖计分题所需方法。生成 `XX-supplement.md`，补齐缺少的概念、示例和演练。日志将责任记录为教学覆盖不足，不写入用户误区。

### 7.3 `assessment gap`

题目越界、含糊或无法可靠区分理解程度。废弃或重写题目，不降低用户状态。若需要再次评估，必须使用对齐后的新题。

### 7.4 用户明确困惑

先进行一次针对性诊断：

- 核心机制仍不清楚：停止依赖该概念的新内容，补充或重新教学。
- 核心正确但边界、迁移或确信度不稳：标记 `provisional`，在两篇内复测。
- 只有术语或表达不精确：澄清并记录低风险残余问题。

## 8. 概念级状态机

| 状态 | 定义 |
|---|---|
| `unseen` | 尚未学习 |
| `learning` | 正在首次学习，证据不足 |
| `provisional` | 方向正确，但边界、迁移、表达或确信度不稳定 |
| `remediating` | 已确认学习缺口，正在换角度教学 |
| `solid` | 当前能解释、迁移、识别边界，且无实质性残余困惑 |
| `durable` | 经过间隔、换场景、无提示复测后仍稳定 |
| `deferred` | 多次处理后仍不稳定，经用户同意暂时后移 |

一个概念达到 `solid` 必须同时满足：

- 正文覆盖充分且题目对齐。
- 用户能用自己的话解释核心机制。
- 用户能在新场景中应用。
- 用户能识别至少一个边界、反例或不适用条件。
- 回答提供了足够判断证据，而非猜测或复述。
- 用户没有报告实质性困惑；低置信度已被诊断。
- 不存在未解决的 `instruction gap` 或 `assessment gap`。

推进由概念依赖决定：下一课依赖的前置概念必须达到 `solid`。不阻塞后续理解的 `provisional` 可以暂时推进，但必须在两篇内复测。`solid` 只有通过延迟复测后才升级为 `durable`。

## 9. Markdown 双层记录

### 9.1 `_progress.md`：当前快照

该文件保持短小，只保存：

- 当前课程位置和下一教学动作。
- 概念状态表。
- 活跃的残余困惑。
- 未解决的教学缺口和题目缺口。
- 即将到期的复测。
- 当前有效的个性化教学策略。
- 供新会话使用的接手摘要。

每个概念至少包含：稳定 ID、状态、教师置信度、用户置信度、最近证据、残余困惑、覆盖状态、下一动作和复测期限。

### 9.2 `_learning_log.md`：追加式证据日志

该文件只追加、不覆盖历史。文件顶部记录 `schema_version: 2`。每个事件使用固定字段：

```markdown
### EVT-YYYYMMDD-NNN

- Timestamp:
- Document:
- Concept IDs:
- Question type:
- Answer reference:
- Evidence summary:
- User confidence:
- Residual confusion:
- Coverage status:
- Gap source:
- Tutor confidence:
- Decision:
- Teaching action:
- Outcome:
- Next review:
```

完整回答保留在课程文档中；日志保存精确引用、关键回答片段和诊断依据，避免机械复制整篇内容。

### 9.3 `_user_profile.md`：稳定个性化信息

只保存背景、目标、表达偏好，以及经过多次验证有效或无效的教学方式。一次性的困惑和当前状态不写入用户档案。

## 10. 每轮学习的数据流

1. 读取 `_user_profile.md`、短小的 `_progress.md` 和当前概念相关的日志事件。
2. 建立教学覆盖清单并确定课程边界。
3. 生成正文及已映射类型的习题。
4. 收集用户答案、置信度和最困惑点。
5. 检查题目对齐并诊断缺口来源。
6. 向 `_learning_log.md` 追加评估事件。
7. 更新 `_progress.md` 当前快照。
8. 根据前置依赖决定推进、暂定掌握、补充讲解或重新教学。

日常教学不得整份读取不断增长的 `_learning_log.md`；应根据概念 ID 搜索并读取相关事件。完整读取只用于审计或迁移。

- 新建 v2 当前状态区和 `_learning_log.md`。

- 对 01-04 只迁移有证据支持的结论，不补造用户置信度。
- 将人工改判验证从笼统 `solid` 调整为与现有证据一致的 `provisional`，保留残余字段困惑和复测计划。
- 09 保持 `learning`，等待用户真实作答后再产生评估事件。

## 12. Skill 文件调整

- `SKILL.md`：质量优先、覆盖检查、概念级判定、记录更新顺序等不可绕过的主流程。
- `references/lesson-design.md`：教学覆盖清单、拆课原则和题目映射。
- `references/grading.md`：状态机、用户置信度、困惑否决、推进与复测规则。
- `references/progress-tracking.md`：双层 Markdown 模板、字段定义和迁移规则。
- `references/remediation.md`：三类缺口及对应教学动作。
- `references/writing-style.md`：教学质量决定篇幅和文档数。
- `references/learning-modes.md`：所有模式统一遵守覆盖、记录和掌握判定规则。

SKILL.md 只保留核心流程，详细模板放入直接引用的 reference 文件，避免重复和无关上下文占用。

## 14. 验证策略

改版前后复用相同的四个独立场景，测试代理只获得原始材料，不获得预期修复方案：

1. 正文覆盖不足但题目要求完整方法，验证是否误设掌握门槛。
2. 答案方向正确但字段含糊，且用户明确表达困惑，验证是否误判 `solid`。
3. 多个紧密概念无法在偏好篇幅内讲透，验证是否自然展开或拆课。
4. 冷启动记录同时存在“已掌握”和残余困惑，验证新会话能否恢复真实概念状态。

每个场景使用独立上下文，先记录当前 skill 的失败行为，再用改版 skill 重跑。验收结果必须满足：

- 越界题不影响掌握判定。
- 用户实质性困惑否决 `solid`。
- 教学缺口不记录为用户误区。
- 教学覆盖决定篇幅和拆课。
- 冷启动能恢复概念级状态和下一动作。
- `_progress.md` 保持当前快照职责，详细证据进入 `_learning_log.md`。
- 不引入 SQL，不读取历史课程。
